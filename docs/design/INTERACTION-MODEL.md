# Interaction Model — Floating Window Three States

> 版本: v1.0 | Iris | 2026-08-06
> 眯聊核心 UX spec：浮窗三态交互模型。

---

## 概述

眯聊的浮窗是整个产品最核心的设计触点。它与普通 app 页面设计逻辑完全不同——浮窗运行在微信上层，需要做到**存在但不打扰**。

三态命名直接对应产品名"眯聊"的交互释义：**眯着 → 睁眼 → 看一眼**。

---

## 态 1: 眯着（常态）

用户正在刷微信，浮窗处于最安静的状态。

| 属性 | 规格 |
|------|------|
| 形态 | 半透明小圆点（直径 44dp）或细条（8×56dp） |
| 位置 | 屏幕右边缘，贴边吸附（edge snap） |
| 透明度 | 60% alpha |
| 颜色 | Slate #475569 |
| 交互 | 可拖拽移动任意位置，松手后自动吸边 |
| 视觉隐喻 | "眯着眼" — 存在但不打扰 |

约束：不遮挡微信内容区域。用户日常刷微信时几乎感受不到它的存在。

---

## 态 2: 睁眼（采集）

用户看到想记录的对话，点击浮窗。

| 属性 | 规格 |
|------|------|
| 触发 | 点击"眯着"态浮窗 |
| 展开形态 | 小浮窗（~120dp 宽），圆角卡片 |
| 内容 | 环形成功进度 + "采集对话中..." 文字 |
| 后台行为 | MediaProjection 截图 + AccessibilityService 自动滚动 + 多图拼接 |
| 时长 | 1-3 秒（取决于对话长度） |
| 完成后 | 自动收回为"看一眼"态 |

约束：
- 采集期间不弹系统对话框（权限已在首次使用时授予）
- 进度指示保持极简——一个环形填充即可，不需要百分比数字
- 用户可以在采集期间继续看微信，浮窗保持在上层但缩小

---

## 态 3: 看一眼（结果）

采集和分析完成，浮窗通知用户结果可查看。

| 属性 | 规格 |
|------|------|
| 触发 | 采集 + AI 分析完成后自动切换 |
| 形态 | 略大于"眯着"态 — 迷你摘要卡片（~180dp 宽） |
| 内容 | 一句话对话摘要 + 待办/决策数量统计 |
| 视觉提示 | 浮窗左上角小红点（pulse 动画，2s 周期） |
| 展开行为 | 点击 → 跳转眯聊 App 内完整报告页 |
| 忽略行为 | 3 秒后自动缩回"眯着"态，红点保留 |

约束：
- 迷你摘要一行截断（ellipsis），不要展开
- 小红点持续显示直到用户查看了报告
- 不发送系统通知——所有反馈都在浮窗内完成

---

## 三态转换图

```
眯着(常态) ──点击──▶ 睁眼(采集) ──完成──▶ 看一眼(结果) ──点击──▶ 眯聊App(完整报告)
   ▲                  │                        │
   │                  │ 取消                   │ 3秒无操作
   │                  ▼                        ▼
   └──────────────────────────────────── 眯着(常态)
```

---

## 设计约束

来自 Harness Engineering 和方法论：
- 浮窗不发送系统通知——所有反馈在浮窗内完成
- 不打断用户的微信使用——采集静默进行
- 三态切换动效使用 fade + scale，禁用弹跳/弹性动效
- Android Overlay API 限制决定最小触摸区域和形态
- 参考 Atlas 的 Android 版本兼容性矩阵调整各版本实现差异
