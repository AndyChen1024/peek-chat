> 每个计划是一个独立的 markdown 文件，命名格式: `YYYY-MM-DD-简短描述.md`

---

## 目标

## 工作流规则

1. **PRD.md → ARCHITECTURE.md → 模块划分 → 任务拆解**
   - 任何功能开发必须从 PRD.md 出发
   - 确认功能在 PRD 中有定义
   - 在 ARCHITECTURE.md 中确认模块位置
   - 在此目录创建执行计划

2. **代码改动前先更新文档**
   - 计划中的设计决策必须先写入相关文档
   - 涉及架构变更的 → 先更新 ARCHITECTURE.md
   - 涉及 UI 组件的 → 先更新 docs/design/COMPONENTS.md
   - 涉及数据模型的 → 先更新 ARCHITECTURE.md 数据模型部分

3. **执行计划归档**
   - DONE 的计划不移除，保留在此目录供审计
   - ABANDONED 的计划保留原因说明
